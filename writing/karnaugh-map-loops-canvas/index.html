Drawing wrap-around Karnaugh map loops on a canvas

A Karnaugh map group can wrap from the top row to the bottom, or the left column to the right, or both at once. Drawing that cleanly without special-casing every shape came down to one observation.

September 18, 2026 JavaScript · Canvas Try the tool

Why I built it

Digital logic homework asks you to simplify Boolean functions with a Karnaugh map: fill a grid with the function's outputs, then circle groups of adjacent 1s whose sizes are powers of two. Drawing those circles by hand and photographing them is fine until you want a typed submission. Every existing tool I found either solved the map for me, which is not the point of the exercise, or produced something ugly.

So K-Map Looper does exactly one thing. You fill the cells, you click which cells belong to each group, and it draws the loops cleanly and exports a PNG. It never simplifies anything. The thinking stays yours.

The grid is a torus

The columns and rows of a K-map are labelled in Gray code order, 00 01 11 10, so that neighbouring cells differ in exactly one variable. That is what makes adjacency mean something logically. It also means the first and last columns are adjacent (00 and 10 differ only in the first bit), and likewise the first and last rows. Topologically the map is a torus, and a valid group can cross either edge.

On paper you draw those as loops that run off one side and come back on the other. On a canvas that is the whole problem: a rectangle with rounded corners is easy, a rectangle that leaves the drawing is not.

Represent a group as rows × columns

A group is a set of cells. A valid group is a rectangle on the torus, so its cells are the Cartesian product of a set of rows and a set of columns. I check that first: 

const rs = unique(cells.map(c => c.row)).sort();
const cs = unique(cells.map(c => c.col)).sort();
const product = rs.length * cs.length === cells.length;

If the cell count does not equal rows × columns, the user has clicked something that is not a rectangle. The tool still draws it, as a dashed outline per cell, so nothing disappears, but it does not pretend it is a group.

Split wrap-around into contiguous runs

A group that wraps horizontally has columns like [0, 3]: the first and the last, nothing in between. Split the sorted indices into runs of consecutive integers: 

function runs(idxs) {
  const out = []; let run = [];
  idxs.forEach(i => {
    if (run.length && i !== run[run.length - 1] + 1) { out.push(run); run = []; }
    run.push(i);
  });
  if (run.length) out.push(run);
  return out;
}
// runs([0, 3]) → [[0], [3]]     runs([1, 2]) → [[1, 2]]

Every combination of a row run and a column run is one rectangular piece to draw. A group that wraps both ways, the four corners of a 4×4 map, produces four pieces. A group that does not wrap produces one.

The observation: a wrapped piece just has open edges

Each piece is still a rectangle. The only difference is that some of its edges should not be drawn, because the loop continues off the map there. Which edges? A piece has an open left edge when it sits in column 0 and the group also contains the last column. Same rule for the other three sides: 

const openL = c0 === 0      && cs.includes(C - 1) && cs.length < C;
const openR = c1 === C - 1  && cs.includes(0)     && cs.length < C;
const openT = r0 === 0      && rs.includes(R - 1) && rs.length < R;
const openB = r1 === R - 1  && rs.includes(0)     && rs.length < R;

The length < C guard matters: a group spanning every column is a full band, not a wrap, and should be closed on both sides.

An open edge does two things. The rectangle extends a little past the map on that side so the loop visibly runs off the edge, and the corners on that side are drawn square instead of rounded, because a rounded corner would suggest the loop closes there.

Then, rather than building four different path shapes, I stroke the full rounded rectangle and paint over the open edges with a slightly thicker white line. It is not elegant. It is about six lines, it works for every combination, and the exported PNG looks exactly like what you would draw by hand.

Nested groups

Groups overlap constantly, a group of four often sits inside a group of eight. Drawing both at the same inset makes them share edges and become unreadable. Each loop gets an inset of 10 + (index % 3) * 7 pixels, so up to three overlapping loops stagger visibly, and each has its own colour from a six-colour palette chosen to stay distinct in the exported image.

Exporting

The canvas is the export. canvas.toBlob() produces a PNG, and where the Clipboard API is allowed it goes straight onto the clipboard for pasting into a document. Where it is not, the tool shows the image inline so it can be dragged or right-click copied, and there is always a download button. The map itself is always rendered on white with fixed dark ink regardless of the page theme, because the export is going into a printed submission.

What it deliberately does not do

It does not check that your groups are valid prime implicants, and it does not tell you the minimal expression. Both would be easy to add. Both would turn a drawing aid into a homework solver, and the entire reason to draw a K-map is to see the groupings yourself.

The tool is one HTML file with no dependencies: use it here or read the source.
