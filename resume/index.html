Event-Driven Commerce Platform

v1.0.0 · Aug 2026

Java 21 · Spring Boot · Kafka · PostgreSQL · Flyway · Docker · Testcontainers · GitHub Actions

  • Built three independently deployable services (order, inventory, payment) that coordinate an order → inventory → payment saga over Kafka with no synchronous calls and no shared database.
  • Implemented a transactional outbox in every service with a multi-replica-safe publisher (FOR UPDATE SKIP LOCKED, bounded 8 s lock hold, cross-replica per-order ordering guard).
  • Made every consumer idempotent with a processed-events ledger claimed inside the mutation's transaction; classified failures into business outcomes, contract violations (dead-letter), and transient errors (exponential backoff).
  • Added optimistic locking on the order aggregate and inventory rows, saga compensation that releases held stock exactly once, and three-layer at-most-once payment charging.
  • 345 automated tests against real PostgreSQL and Kafka, including latch-driven concurrency proofs and a 16-test end-to-end suite running all services as containers; all suites run in CI.

Case study: ahmet-keles.github.io/projects/event-driven-commerce · Source: github.com/ahmet-keles/event-driven-commerce
